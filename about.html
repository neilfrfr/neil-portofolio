About

Computer Science student who learns by building.

A closer look at how I got here, what I currently work with, and how I approach a new problem.

Hello — I've been tinkering with hardware and software since high school.

That habit started early: taking apart hardware and poking at code side by side, long before any of it was coursework. It's the same instinct that still drives how I learn today — open it up, see how it works, then build something with it.

Fast-forward to today, and I've had the privilege of studying Computer Science at an advanced level. My main focus these days is building accessible, inclusive products and digital experiences for a variety of users. I'm a continuous learner, always exploring new frameworks, languages, and technologies to optimize my workflow.

This site is one example of that: it's a self-built academic directory backed by Firebase Authentication and Firestore, with Cloudinary handling file uploads — no drag-and-drop site builder, no template backend.

Approach

How I work

01

Learn by building

Concepts stick once I've actually shipped something with them — this portfolio's live database is a product of that, not a class assignment.

02

Read the docs first

Before wiring up a new service — Firebase rules, Cloudinary presets — I go through the documentation instead of guessing at defaults.

03

Iterate in the open

I'd rather ship a working, honest version of something and improve it than hide an unfinished idea until it's "done."

04

Document as I go

Setup steps, configuration, and decisions get written down — for teammates, for evaluators, and for future me.
